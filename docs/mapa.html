Como o Securo fica em pé neste PC

O app mora no Docker local. O código seu mora no fork. O dinheiro dos dados mora no Proton. A comunidade só entra no horário do carimbo.

Rua

comunidade · upstream/main

Projeto oficial: securo-finance/securo.

Eles soltam o main. A gente puxa isso; não mandamos o nosso código para eles.

Oficina

seu fork · origin/lucas

GitHub Soutto/securo, branch lucas.

Aqui ficam os patches (logs, compose local, este mapa). Fork é público: nunca .env, nunca senha GPG.

todo dia 12:30 backup + update
Corredor
das 12:30
  1. Backup GPG e sobe no Proton Drive
  2. Rebase de upstream/main em lucas
  3. Build Docker (prod + lucas) e sobe o app
  4. Push no fork, se o GitHub estiver logado

Mesa

este computador · localhost

Abra http://localhost:3000. Portas só em 127.0.0.1.

  • Pasta: ~/Projects/securo
  • Compose: docker-compose.prod.yml + docker-compose.lucas.yml
  • Dados: volumes securo_pgdata, anexos, knowledge — nunca sincronizar ao vivo
  • Timer systemd do usuário: se o PC estiver desligado, roda no próximo login

Cofre

Proton · Pass + Drive

Backup: proton:Backup/securo (arquivo .tar.gz.gpg).

No Proton Pass: senha do app, senha da conta Proton, senha GPG do backup.

O PDF de recuperação da conta Proton precisa existir fora do Proton (papel). Sem ele, Pass e Drive caem juntos.

Nunca

  • Rodar o git pull && docker compose up que o diálogo “Atualização do servidor” sugere — ele só checa release; o update de verdade é securo-update.
  • Mandar .env ou a senha GPG para o GitHub.
  • Conectar banco direto no widget da Pluggy. Uso pessoal: MeuPluggy.
  • Sincronizar a pasta dos volumes Docker com o Drive.

Cadeia de chaves

App SecuroLogin em localhost. Senha no Proton Pass.
GPG do backupArquivo local ~/.config/securo/backup-passphrase. Cópia no Proton Pass.
Conta ProtonAbre Pass e Drive. Senha + 2FA no Proton Pass.
PDF ProtonÚltima chave se a conta travar. Impresso; não deixar só dentro do Proton.
GitHub SouttoPush da branch lucas. gh auth login se o timer não conseguir enviar.

Se o rebase brigar

O script aborta o rebase, deixa o app na versão que já estava, e grava falha no menu Log de backup e update (últimos 5).

Se houver arquivo sem commit, o update das 12:30 também pula — por isso a branch precisa estar limpa.

rclone do Zorin (1.60) não fala com Proton. O certo é o binário em ~/.local/bin/rclone.

securo-backup securo-update securo-restore --from-drive securo-proton-login
PC novo: cole o conteúdo de SETUP-MAQUINA.txt no Cursor e faça os logins quando o agente pedir. Bancos: MeuPluggy, não Itaú/Nubank direto. Keep local 3 arquivos; Proton apaga .gpg com mais de 14 dias.
